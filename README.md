# Rent·Control

Telegram Mini App для обліку оренди, роботи, цілей і активів. Усі дані — у твоїх базах Notion.

## Що всередині (v5)

- **Пульс** — заробіток місяця з графіком за пів року (пальцем можна «прогорнути» місяці), прогноз місяця (оплати оренди, що ще мають прийти, плюс темп роботи за 4 тижні — з розбивкою), найближчі оплати, звіт за день / тиждень / місяць / рік (доходи й витрати по категоріях, ліміти на категорії), тренд за рік, капітал «Усе разом» (картки + біржі + монети).
- **Оренда** — живий лічильник доходу, статуси оплат, пошук і фільтри, картка орендаря зі шкалою оплаченого періоду, нагадування в Telegram з готовим текстом, реферальні бонуси, аналітика «виконано / наперед». «Схоже на оплату»: надходження на картку, що збігаються з орендарем (імʼя відправника й сума), зараховуються одним натиском з датою з банку.
- **Робота** — календар-теплокарта годин, категорії зі ставками, підробітки, виплати (аванс / фактична, загальні чи по категорії), архів місяців.
- **Капітал** — рахунки (Монобанк і біржі Bybit, BingX, MEXC з балансами наживо), цілі з рівнями й прогнозом, крипто-портфель з графіком, середньою ціною й P&L; монети з бірж додаються до портфеля самі.
- **Автоімпорт витрат** — кожна оплата карткою Монобанку сама записується у витрати Expense·Control з категорією (за магазином і MCC); перекази, готівка й надходження не рахуються витратами. Можна імпортувати й виписку за 31 день з переглядом і вибором категорій, без дублів.
- **Історія й аналітика по місяцях** — кожна операція Монобанку й кожне поповнення/виведення на біржах зберігається в Notion (база «Рух коштів»: застосунок створює її сам поруч з іншими базами або знаходить створену вручну). Вікно «Історія»: будь-який місяць, фільтр за карткою чи біржею, пошук за назвою, коментарем чи сумою, графік за рік; у «Пульсі» → «Звіт» — блок «Рахунки й біржі». «Регулярні платежі» — підписки й щомісячні перекази знаходяться самі, з датою наступного списання й позначкою, якщо щось подорожчало. Минулі 12 місяців підтягуються у фоні (Монобанк віддає одну виписку на хвилину).
- **Сповіщення в бот** (необовʼязково, за замовчуванням вимкнені) — операції Монобанку миттєво, поповнення й виведення на біржах — через щохвилинну перевірку (cron-job.org).
- **Цей пристрій** — вхід через Face ID / Touch ID / відбиток (Telegram BiometricManager): під час відкриття й після 3 хв у фоні, вмикається окремо на кожному пристрої; іконка застосунку на головному екрані.
- Швидке додавання з центральної кнопки, «Скасувати» після видалення, робота з кешу, якщо Notion недоступний, світла й темна теми (за Telegram).

## Збірка

```bash
npm install
npm run build   # → dist/ — це й публікує Vercel
npm run demo    # → dist-demo/index.html — офлайн-демо з фейковим Notion і демо-даними
```

Параметри демо: `?theme=light`, `?empty=1` (без даних), `?lat=600` (затримка «Notion», мс), `?banks=0` (банки й біржі не підключені), `?ledger=0` (історія ще не ввімкнена), `?bio=face|finger|none` (біометрія пристрою), `?biofail=1` (перевірка не проходить).

Тести серверної частини (підпис Telegram, доступ до записів, Монобанк, біржі, імпорт витрат — з фейковими відповідями): `node dev/tests/server.test.cjs`.

## Структура

```
src/lib/        дати, гроші й курси, доменна логіка (rent, work, overview, capital), Notion (schema, api)
src/state/      сховище, стан інтерфейсу, дії (оптимістичні записи, відкати, синхронізація)
src/screens/    Пульс, Оренда, Робота, Капітал
src/sheets/     нижні вікна: форми, картки, підтвердження, налаштування
src/ui/         дизайн-система: іконки, графіки, компоненти, вікна
dev/            фейковий Notion (сувора перевірка колонок), демо-дані, вхід демо-збірки
api/            функції Vercel: проксі до Notion (білий список баз, перевірка підпису Telegram), CoinGecko,
                finance.js — банки й біржі (баланси, вебхук Монобанку, імпорт витрат)
api/_lib/       спільне для функцій: підпис Telegram, Notion, Монобанк, біржі, категорії витрат
```

## Змінні у Vercel

```
NOTION_TOKEN
DB_CLIENTS  DB_PAYMENTS  DB_WORK_ENTRIES  DB_WORK_CATEGORIES  DB_PAYOUTS
DB_EXPENSES  DB_CAT_EXPENSES      — з Expense·Control (витрати у звітах і автоімпорт)
DB_GOALS  DB_GOAL_TX              — модуль «Цілі» (необовʼязково)
DB_ASSETS  DB_ASSET_TX            — модуль «Активи» (необовʼязково)
```

`DB_INCOMES`, `DB_CAT_INCOMES`, `DB_REGULARS` застосунок не використовує.

### Захист даних

```
TG_BOT_TOKEN      — токен бота з @BotFather (API Token)
OWNER_TG_ID       — твій Telegram ID: власник ключів банків і бірж
ALLOWED_TG_IDS    — необовʼязково: кому ще дозволено відкривати застосунок (через кому)
```

З `TG_BOT_TOKEN` сервер приймає тільки запити, підписані Telegram (заголовок `X-Telegram-Init-Data`, підпис не старший 7 днів), і сам обмежує кожен запит записами цього користувача: читання — за колонкою `Telegram ID` (плюс «Загальні» категорії), створення — завжди з ID користувача, зміна й видалення — лише власних записів у базах з білого списку. Без `TG_BOT_TOKEN` проксі працює як раніше (відкрито), а банки й біржі не віддаються взагалі.

### Банки й біржі

```
MONO_TOKEN                          — особистий токен з api.monobank.ua (лише перегляд)
BYBIT_API_KEY   BYBIT_API_SECRET    — ключ Read-Only
BINGX_API_KEY   BINGX_API_SECRET    — ключ лише Read
MEXC_API_KEY    MEXC_API_SECRET     — ключ лише View/Read
BYBIT_HOST                          — необовʼязково: api.bybit.com / api.bybit.eu (визначається сам)
APP_TZ                              — необовʼязково: часовий пояс дат витрат, за замовчуванням Europe/Warsaw
DB_LEDGER                           — необовʼязково: ID бази «Рух коштів» або просто посилання на неї з Notion (інакше знаходиться за назвою)
```

Ключі бірж — без дозволів на торгівлю й виведення і без привʼязки до IP. Функції працюють у регіоні `fra1` (Франкфурт): біржі блокують запити зі США. Після зміни змінних — **Redeploy** у Vercel.

Вебхук Монобанку: перемикачі «Історія операцій», «Записувати покупки у витрати» і «Сповіщення в Telegram» у «Капітал → Рахунки → Підключення» реєструють `/api/finance?hook=mono&k=…&log=…&imp=…&ntf=…` (секрет виводиться з `MONO_TOKEN`, налаштування зберігаються в самій адресі). Для захисту від дублів сервер сам додає в базу витрат Expense·Control текстову колонку `Банк ID`; у «Русі коштів» вона є від початку.

Історія: базу «Rent·Control · Рух коштів» сервер створює на сторінці, де лежать інші бази (інтеграція Notion має мати доступ до цієї сторінки — Connections). Колонки: Назва, Сума (зі знаком), Валюта, USD, Дата, Тип, Рахунок, Опис, Банк ID, Telegram ID. Базу можна створити й вручну: сервер сам перейменує колонки з іншим написанням («telegram id» → «Telegram ID»), додасть відсутні й виправить типи (Сума, USD, Telegram ID — числа, Дата — дата; Валюта, Тип і Рахунок можуть бути й текстом). Що виправити не вдалось, застосунок показує на картці «Історія» з назвою колонки й потрібним типом.

Сповіщення про біржі: біржі не надсилають подій, тож зовнішній розклад (cron-job.org, щохвилини) смикає `/api/finance?hook=poll&k=…`; адресу з секретом (виводиться з `TG_BOT_TOKEN`) застосунок показує власнику. Бот пише першим лише після того, як у чаті з ним натиснуто «Почати».

## Сумісність з Notion

Назви й типи колонок, формати значень — ті самі, що у v3: нова версія читає й пише ті самі бази без змін.
